# 0257 — Five wiki links 404, and a paths: trigger for a page nothing publishes

**Issue:** [#0257](https://github.com/CyrilB1531/lodestar/issues/0257) · **Status:** accepted — **retrospective**, written 2026-08-29 from the commits that closed it · **Date:** 2026-08-18

## Problem

Five links 404 for a wiki reader, from two causes: `zerodivision.md` named `regression.md` as a sibling **one directory too deep**, so `build_wiki.py` left it unrewritten; four more pointed out of `docs/` at repository files the wiki does not publish.

Separately, `CONTRIBUTING.md` sat in the Wiki workflow's `paths:` while `wiki-map.json` does not publish it — so **every edit to it started a run that concluded the wiki already matched the tree**.

## What was decided

**Resolve every link on the generated tree, not on `docs/`.** That is the only place the flat `{channel}-{stem}` naming exists, so it is the only place a link can be checked against what a reader will actually see. Checking against `docs/` is checking against a layout the wiki does not have.

The four out-of-tree links become absolute URLs, which resolve from the repository **and** from the wiki.

## What shipped

The five links, the `paths:` correction, and a check that asks the generated tree.
